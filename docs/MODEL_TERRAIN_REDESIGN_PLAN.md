# 模型与地形视觉整改计划

主动模式：`reproduce/modify`。

本轮目标是优化铲雪车模型和 Gazebo 地形观感，同时保持复现语义稳定。第一轮只改视觉层和文档，不改变：

- 驱动关节名：`left_drive_wheel_joint`, `right_drive_wheel_joint`
- 机器人根坐标：`base_link`
- 控制话题：`/cmd_vel`
- 测速话题：`/odom`
- 默认地形摩擦系数、接触刚度和阻尼

## 1. 纸面对齐依据

| 论文/资料位置 | 要求或描述 | 当前代码位置 | 当前结论 |
| --- | --- | --- | --- |
| `扫雪机器人论文_初稿.docx` 第 2 章，2.1-2.2 | URDF 应包含车体、履带行走机构、扫雪铲、传感器、质量/惯量和关节关系 | `urdf_generator.py` | 主结构对齐，但外观主要由 box/cylinder 组成，视觉细节不足 |
| `扫雪机器人论文_初稿.docx` 第 3 章，3.1-3.2 | Gazebo 多地形应覆盖沥青、雪地、沙地、冰面、草地、坡道，并配置摩擦、刚度、阻尼 | `world_generator.py` | 物理参数基本对齐，但地形外观是单色平板 |
| `扫雪机器人论文_初稿.docx` 第 3.3 节 | LiDAR、IMU、里程计为核心仿真传感器 | `urdf_generator.py` | LiDAR/IMU 已实现，里程计由 diff_drive 插件发布 `/odom` |
| `扫雪机器人论文_初稿.docx` 第 4 章 | TAVCC 地形自适应速度修正节点 | 当前代码缺失完整 ROS 节点 | 本轮不擅自补写，避免改变实验语义 |
| `扫雪机器人论文_初稿.docx` 第 5 章 | PMSM 速度环、电流环、前馈控制 | `control_prototype.py`, `snowplow_control/` | Python 原型和 C++ 插件骨架存在；Ubuntu 编译验证由用户执行 |

## 2. 现有纰漏

| 问题 | 类型 | 影响 | 本轮处理 |
| --- | --- | --- | --- |
| 铲雪车外观过于简单 | 可视化/展示 | 不利于论文、汇报和演示 | 增加车体层次、履带细节、灯具、传感器支架、铲刀边缘 |
| 地形是纯色块 | 可视化/展示 | 很难直观看出雪、沙、冰、草差异 | 增加视觉纹理块、边界、雪堆/沙纹/冰裂、路面线 |
| 坡道只有阶梯块 | 可视化/展示 | 功能可用但观感机械 | 后续再补坡道视觉细节 |
| `output/urdf/snowplow_robot.urdf` 是编译中间文件 | 文件整理 | 可由 xacro 重新生成 | 删除，保留 `.xacro` 源文件 |
| `ros2_control.yaml` 与自定义 `pmsm_controller` 链路不完全统一 | 复现风险 | 切换 ros2_control 时可能混淆 | 本轮记录风险，不在视觉改造中改变控制语义 |
| 第 4 章 TAVCC 节点缺失 | 论文复现缺口 | 不能声称完整复现第 4 章 | 保留为后续语义级任务 |

## 3. 方案选择

| 方案 | 内容 | 选择 |
| --- | --- | --- |
| A：视觉增强，碰撞和控制不变 | 给 URDF/SDF 增加视觉元素，collision/inertial 和物理参数尽量不动 | 本轮采用 |
| B：引入 mesh/贴图资产 | 用 STL/DAE/纹理图提升真实感 | 后续可做，当前不依赖外部资产 |
| C：重写履带动力学或 TAVCC | 改控制/地面动力学语义 | 本轮不做，需要单独确认 |
| D：删除历史实验输出 | 清空 `terrain_output/benchmark_output/figures` | 不推荐，可能是报告证据 |

## 4. 插件/工具建议

- `imagegen`：适合后续生成雪地、沥青、沙地、草地、冰面贴图。
- `browser`：适合查 Gazebo Classic SDF/URDF 官方语法，但本轮先用标准几何体避免依赖。
- `create-figure` 或 `scientific-svg-figures`：适合后续画系统结构图、复现流程图或论文方法图。

## 6. 本轮完成标准

- `urdf_generator.py` 默认生成更像工程样机的铲雪车；
- `world_generator.py` 默认生成更有辨识度的多地形场景；
- 不破坏既有新手复现命令；
- 删除明确可再生的中间文件；
- README/指南说明新增视觉增强和剩余风险。
